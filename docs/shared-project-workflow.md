# مشروع واحد، جميع مواد المزاد

المسار الافتراضي هو **إنشاء مشروع ← بيانات المشروع ← الكتيّب / البنرات / منشورات التواصل ← المراجعة والاعتماد والتنزيل**.

- تُحفظ بيانات المزاد والعقارات ووكيل البيع والشعارات والصور مرة واحدة تحت رقم مشروع واحد.
- خطوات «بيانات المشروع»: المزاد والغلاف، وكيل البيع، العقارات (يدويًا أو قالب الإكسل المعتمد)، والصور.
- «الكتيّب»: مراجعة البيانات والتوليد ثم المخرجات.
- «البنرات» و«منشورات التواصل»: التصميم والمقاس واختيار العقارات، المراجعة والتوليد، ثم المخرجات. رابط أي نقص في البيانات يفتح القسم المشترك المناسب.
- «جميع مخرجات المشروع» تجمع الملفات الثلاثة بإصداراتها واعتماداتها. إنشاء نوع جديد لا يُنشئ مشروعًا أو ينسخ العقارات والصور.
- صفحات البنرات والمنشورات في القائمة الجانبية تعرض أولًا المشاريع الموجودة لاستخدام بياناتها. إنشاء حملة مستقلة زر صريح إضافي. نموذج المشروع يتيح أيضًا اختيار «كتيّب مستقل فقط».

## التحديثات وحماية الاعتماد

تغيير بيانات المشروع أو عقاراته أو صوره يطلب إعادة توليد المخرجات قبل الاعتماد أو التصدير. تغيير مقاس البنر أو إعدادات المنشور فقط لا يبطل اعتماد الكتيّب أو النوع الآخر. لا تعود المخرجات القديمة إلى الاعتماد تلقائيًا عند إجراء تعديل لاحق. إعادة توليد نسخة سبق اعتمادها تحفظ النسخة السابقة وتنشئ مسودة جديدة.

تظل مراجعة النواقص والمقاسات وقص النصوص، وحدود ملكية المستخدمين للمشاريع والملفات، مطبقة في الأقسام الثلاثة.

## التوافق

نوع project هو الافتراضي. يرقّي الترحيل 0006 مشاريع الكتيّبات السابقة إلى مشاريع مشتركة في مكانها، مع الحفاظ على المعرّفات والبيانات والعقارات والصور والملفات. الحملات المستقلة من نوع banners وsocial تبقى مستقلة. النوع booklet متاح للاختيار المستقل ولتوافق المخرجات القديمة.

الاختبارات: test_shared_projects.py وshared-project.spec.ts تغطي التوليد المشترك، عدم تكرار البيانات، تأثير التعديلات، الاعتماد، والواجهة على الجوال.
