# ملف وكيل البيع على الحساب

بعد تسجيل الدخول، تظهر صفحة إكمال الملف لمن لم يؤكد بياناته بعد: الاسم، الوصف، رقم التواصل والشعار مطلوبة. الموقع وواتساب ووسائل التواصل الإضافية اختيارية. تتاح الصفحة لاحقًا من «إعدادات حسابي» للمستخدم والأدمن، بشكل منفصل عن إعدادات النظام.

تُعرض بيانات أحدث وكيل محفوظ في مشاريع الحساب كتعبئة مبدئية للحسابات القديمة، ولا تُعتمد حتى يحفظها المستخدم. لا تُنسخ بيانات حساب آخر. تُنشأ المشاريع الجديدة ببيانات الوكيل وشعاره تلقائيًا؛ لا توجد خطوة وكيل في الكتيّب أو البنرات أو المنشورات، ولا يُرفع شعار الوكيل من المشروع.

حفظ الملف يحدّث بيانات الوكيل في جميع مشاريع الحساب داخل معاملة واحدة. المخرجات السابقة تُعلّم بأنها تحتاج إعادة توليد، مع الاحتفاظ ببياناتها وملفاتها القديمة دون إعادة كتابة. حفظ نفس البيانات دون تغيير لا يغيّر مراجعة المشاريع. بعد إكمال الملف تُرفض محاولة تخصيص الوكيل عبر واجهة المشروع القديمة.

الترقية `0007` تضيف عمود JSON لملف الوكيل في جدول المستخدمين. لا تغيّر البيانات القديمة أثناء الترقية. يظل الشعار في مخزن الملفات الخاص، وتستخدم المشاريع مراجع خاصة بها إلى نفس الملف. القراءة والتعديل مرتبطان بالمستخدم المسجّل؛ لا تقبل الواجهة مسار ملف أو معرف شعار من العميل.

الواجهة: `GET/PUT /api/account/profile`، والشعار `GET /api/account/profile/logo`. الحفظ multipart بحقل `data` (JSON) وملف `file` اختياري عند وجود شعار سابق. يعيد تسجيل الدخول و`/auth/me` علم `profile_complete` لتوجيه الإكمال مرة واحدة.
